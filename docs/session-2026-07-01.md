### 1. Code review — Portal de Solicitudes (autoservicio de empleado)

Revisión estática (workflow `code-review`, esfuerzo `xhigh`) del diff `d3edc08~1..57eaf1a` en `feature/reportes`, que agrega autoservicio de empleado sobre solicitudes (crear/editar/cancelar las propias) vía `/portal/solicitudes/*`.

**2 hallazgos corregidos** en `src/Controllers/PortalController.php`:

| # | Problema | Fix |
|---|---|---|
| 1 | El filtro `estado` de `mis_solicitudes` aceptaba cualquier string de la query string sin validar contra el enum de la BD (`pendiente`/`aprobada`/`rechazada`). | Se restringe con `in_array($params['estado'] ?? '', ['pendiente', 'aprobada', 'rechazada'], true)`; cualquier otro valor se descarta a `null`. |
| 2 | En la ruta de edición, `array_merge(['id_solicitud' => $id], $datos)` dejaba que el body del POST pisara `id_solicitud` si el formulario enviaba ese campo. | Se invirtió el orden: `array_merge($datos, ['id_solicitud' => $id])`, de forma que el id de la ruta siempre gana. |

Verificado con `vendor/bin/phpunit` — 31/31 pruebas, 61 aserciones, sin regresiones.

**4 hallazgos de severidad menor quedaron diferidos** (a pedido explícito del usuario, no se tocaron):

- Lógica de autorización duplicada entre `editarSolicitud` y el resto del servicio.
- Control `filtroEstado` del template sin conectar al backend.
- Parámetro `$request` sin usar en `idEmpleadoOFlash`.
